## 二、核心设计：Server-Authoritative 信息隔离

### 设计原则

AI Agent **绝不直接互相调用接口**。所有 Agent 只与 FastAPI 后端通信，由 Game Master 负责信息过滤、规则校验和消息分发。

### 信息信道分层

```

                    │  Game Master │
                    │   (裁判系统) │

                       │  │  │  │
          ┌────────────┼──┼──┼──┼────────────┐
          │            │  │  │  │            │
          ▼            ▼  ▼  ▼  ▼            ▼
    ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐

```

  │                                │

  │◄─── game_start (role+teammates)───│

  │──── ready ───────────────────────►│
  │                                │  等待所有玩家 ready
  │◄─── phase_change ───────────────│  进入 night_wolf

### 阶段职责

| 阶段 | 行动者 | 输入 | 输出 |
|------|--------|------|------|
| `night_wolf` | 狼人 | 队友列表、存活玩家 | 击杀目标（需共识） |
| `night_seer` | 预言家 | 验人历史 | 查验一名玩家身份 |
| `night_witch` | 女巫 | 被刀玩家ID、药水状态 | 是否使用解药/毒药 |
| `night_result` | 系统 | 所有夜间行动 | 死亡名单 |
| `day_start` | 系统 | 死亡名单 | 公开死讯公告 |
| `speech` | 全体存活者 | 公开信息 | 发言内容 |
| `vote` | 全体存活者 | 发言记录 | 投票目标 |
| `day_end` | 系统 | 投票结果 | 放逐玩家/检查胜负 |

## 五、数据模型

### 核心实体

```
Game
├── game_id: str (PK)
├── board_type: str
├── status: enum[created, running, finished]
├── phase: enum[night_wolf, ..., day_end]
├── round: int
├── winner: enum[good, evil] | null
├── created_at: datetime
└── players: List[Player]

Player
├── player_id: int (0-5, seat)
├── name: str
├── role: enum[werewolf, seer, witch, villager]
├── is_alive: bool
├── is_sheriff: bool
├── has_voted: bool
└── vote_target: int | null

ActionLog
├── id: int (PK)
├── game_id: str (FK)
├── round: int
├── phase: str
├── player_id: int
├── action_type: str
├── action_data: JSON
├── thought_chain: str       # Agent CoT 内心独白
└── timestamp: datetime
```

### WebSocket 消息模型（Pydantic Discriminated Union）

```python
# 下行消息
ServerMessage = Union[
    GameStartMessage,      # type="game_start"
    PhaseChangeMessage,    # type="phase_change"
    PrivateInfoMessage,    # type="private_info"
    PublicBroadcastMessage,# type="public_broadcast"
    ActionRequestMessage,  # type="action_request"
    GameOverMessage,       # type="game_over"
]

# 上行消息
ClientMessage = Union[
    ReadyMessage,          # type="ready"
    ActionMessage,         # type="action"
    SpeakMessage,          # type="speak"
    SelfDestructMessage,   # type="self_destruct"
]
```

## 六、Agent 设计模式

### 基本结构

```
BaseAgent
├── player_id: int
├── role: str
├── memory: List[MemoryEntry]     # 累积记忆
├── prompt_template: str          # Jinja2 模板引用
│
├── async receive(msg: ServerMessage) → None
├── async think(context: dict) → str       # CoT 推理
├── async decide(valid_actions: list) → Action  # 决策
└── async remember(entry: MemoryEntry) → None
```

### 各角色 Agent 差异化

| 角色 | 记忆模块 | 决策策略 | Prompt 重点 |
|------|----------|----------|-------------|
| 狼人 | 队友ID、击杀历史 | 团队共识 → 兜底随机 | 欺骗策略、角色扮演、悍跳模板 |
| 预言家 | VerifiedList（查验历史） | 信息驱动、逻辑链 | 验人信息珍贵性、报验人顺序策略 |
| 女巫 | 被刀记录、药水状态 | 资源管理、局势判断 | 解药使用时机、自救策略 |
| 平民 | 发言记录、投票行为 | 逻辑分析、行为模式 | 表水技巧、站边逻辑、禁编信息 |

## 七、容错与兜底策略

| 场景 | 策略 |
|------|------|
| Agent 超时未响应 | 狼人→空刀；神职→跳过；平民→弃票 |
| LLM 输出解析失败 | 重试1次，仍失败走兜底默认动作 |
| 狼人团队意见不合 | 强制空刀（避免随机刀破坏游戏体验） |
| Agent WebSocket 断连 | 自动重连，重连期间走兜底 |
| GPU OOM | asyncio.Semaphore(2) 限流，排队推理 |
| Prompt 需要调整 | /api/v1/config/reload 热重载，无需重启 |
